# Ридер в Telegram Mini App

Ридер сохраняет статический сайт и добавляет голосовой разбор выбранной фразы через Telegram Serverless и Gemini Live. Кнопка «Обсудить» в подсказке начинает разговор; кружок внизу завершает его. Озвучка главы или фразы, сворачивание приложения и уход со страницы также отключают микрофон.

`startReaderCall` получает проверенного платформой Telegram-пользователя, идентификатор книги и границу чтения. Сборка генерирует серверный book-data.js с текстом, переводами и заметками из тех же публичных книг, что используются ридером; сервер читает его без сетевой загрузки. При запуске из топбара передаётся литовский текст до конца видимой части экрана; из tooltip — до выбранной фразы включительно и отдельно её оригинал с ударениями, перевод и вся грамматическая заметка. Язык отображения ридера на этот контекст не влияет. Последующий текст и заголовки не передаются. Клик на другую фразу обновляет контекст текущего разговора без выдачи нового токена и без самостоятельного ответа агента.

Одноразовый временный токен ограничивает модель, учебную инструкцию и аудио. Постоянный Gemini API key остаётся на сервере. По умолчанию: одна активная беседа на пользователя, до 10 минут за разговор, 10 минут в день по UTC и 10 секунд между началами разговоров. Неуспешное подключение не списывает разговорное время; heartbeat учитывает активный разговор. Дополнительно сервер атомарно ограничивает число выдач токена до 30 в день: клиентские end/heartbeat этот счётчик не сбрасывают. Учёт 10 минут зависит от клиента, жёсткий предел — 30 токенов по максимум 10 минут. Неудачный запрос Gemini также расходует одну попытку.

В локальном `.env` нужны `GEMINI_API_KEY`, `TG_ACCESS_TOKEN` и `TG_BOT_TOKEN`. Эти значения не включаются в Git и публичную сборку.

```sh
npm install
npm test
npm run build
npm run cloud -- push
npm run cloud -- migrate
node scripts/configure-reader-bot.mjs
```

Сборка `dist/` содержит только ридер, каталог, книги и готовые аудио глав с manifest. Фрагменты фраз воспроизводятся с существующих GitHub Pages; это укладывает сборку в предел 1000 файлов Telegram Serverless. Досье автора, инструменты разработки и секреты исключены. `push` загружает готовую сборку; изменения схемы базы применяются отдельно через `migrate`. На GitHub Pages доступны чтение, перевод и записанная озвучка; голосовой разговор открывается в Telegram Mini App.

В Telegram позиция сохраняется endpoint readingPosition в reading_positions по проверенному userId и книге. Ридер сначала загружает профиль, затем восстанавливает абзац и смещение; полка читает тот же профиль. Последовательная очередь записей не даёт старому запросу перезаписать новый. В обычном браузере сохраняется прежний localStorage.

Все пять настроек (шрифт, размер, тема, язык и голос) Mini App загружает из reader_profiles через readerSettings и сохраняет туда последовательной очередью; localStorage в Telegram не используется. Голоса называются Eglė (Sulafat, по умолчанию) и Marius (Charon). Смена голоса применяется в следующем разговоре. В обычном браузере кнопки ассистента открывают tooltip со ссылкой на бота.

Активный кружок измеряет RMS микрофона и фактически воспроизводимого звука через AudioWorklet и AnalyserNode: голос читателя уменьшает размер, голос преподавателя увеличивает; водяные SVG-волны ускоряются во время ответа, изменения громкости добавляют плеск и небольшие брызги внутри кружка. Кнопка топбара остаётся неподвижной. В режиме reduced-motion движения отключены.

Ссылки каталога сборки Mini App используют reader?book=…: Serverless канонизирует .html-пути и теряет query при редиректе. Исходный каталог для GitHub Pages сохраняет reader.html.

Интерфейс ридера и полки, сообщения об ошибках — на русском. Активный кружок 86 px расположен внизу без значков и видимой подписи; при соединении и завершении звучат короткие мягкие сигналы Web Audio.
